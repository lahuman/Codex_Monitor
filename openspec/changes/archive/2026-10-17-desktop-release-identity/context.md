# Desktop identity and release workflow

The visible product is Codex Monitor 0.1.0. Product name/version come from desktop/src-tauri/tauri.conf.json, shared with the embedded about dialog. The internal bundle identifier remains local.codex-lb.desktop.preview so existing account and history storage remains available. Technical Cargo/npm package names remain stable. The original SVG quota-ring/check/status icon follows the warm dashboard palette; macOS representations are generated with the installed Tauri CLI. ICNS chunks are parsed and sorted by their four-byte type at the generation owner, retaining unchanged image data and producing identical files on consecutive runs. No third-party brand mark is used.

## Build and installation

Prepare dependencies with frontend bun install --frozen-lockfile and desktop npm ci. Use npm run dev inside desktop for development, npm run build for an optimized app, npm run build:preview for debug, and npm run package:macos for a distributable build. Packaging regenerates icons, builds the app, reads actual bundle name/version/identifier, detects Mach-O architectures, and creates desktop/releases/<version>/macos-<architecture>/. This includes the .app, versioned DMG and ZIP, SHA256SUMS.txt and release.json. The DMG contains an Applications symlink and installation instructions. The app includes the upstream MIT license text. Drag the app to Applications after quitting an older running copy. Existing release folders are never silently overwritten. Intel output can be built on an appropriate toolchain but only Apple Silicon was produced and tested here.

The minimum macOS setting is 13.3, aligned with the Safari 16.4 baseline of Tailwind CSS v4 (https://tailwindcss.com/docs/compatibility). This is a configured minimum, not a claim of testing every OS version. Actual QA used the current local Mac.
