# Verification and migration

The Windows-only publication owner was refactored/renamed to publish-desktop-release.mjs and its tests renamed likewise. Active workflow/document consumers no longer reference the superseded filenames. The workflow retains desktop-windows.yml for existing URLs but is displayed as Desktop release. A native macos-15 job explicitly requires uname -m=arm64 and performs locked installs, native Rust/UI tests, package build, native macOS distribution verification and same-run artifact upload. GitHub's current official runner reference lists macos-15 as Apple Silicon for public repositories; no Intel build is claimed. The publication job depends on both native jobs and uses separate download directories and write-scoped permissions.

A shared desktop-v<version> lightweight tag and common release marker replace platform-specific tags for new combined releases. Old Windows-only tag/release routes are not looked up or modified. Both platform manifests must match the checked-out product/version and their expected architectures and exact files. Mac signing/container/installer verification facts are required and propagated accurately. Seven assets are staged and verified before publication: Windows setup, Mac DMG/ZIP and platform-specific metadata/checksum pairs. Release notes include distinct Mac and Windows download links and actual Mac trust/signing facts. A partial Mac upload cannot publish a Windows-only release.

All six production-publisher contract tests passed with a simulated GitHub API and explicit non-native publication fixtures. They cover seven-asset publication order; idempotent public retry; partial failures before and during Mac asset upload; missing server digests with binary download hashing; branch/repository/event eligibility and main freshness; tag/release ownership conflicts; invalid Windows files/metadata and corrupted/incomplete public assets; missing Mac artifacts, mixed versions/architectures, failed signing/container/installer verification, corrupted files/checksum documents and duplicate paths. Download links and trust notes are asserted. These tests do not establish actual GitHub API publication or a new native Windows build.

The new combined validator also read the existing real 0.1.10 Mac DMG/ZIP/metadata/checksum files alongside a labeled simulated Windows fixture and produced the expected seven assets. All five existing real macOS distribution/installer tests passed, including strict signatures, archive round-trips, native Installer resources/payload and read-only DMG mounts. No new Mac app was built because runtime/packaging source and version were unchanged. No installed app/account data changed.

Actionlint passed. Strict OpenSpec validation passed for the renamed/modified change and all 74 main specs. MkDocs strict and 91 source/document/image links passed. Native CI execution of the new macOS job and actual remote combined publication remain unverified until the user commits/pushes and executes the workflow; local artifact validation is not that claim. Recipient-machine installation/sign-in remains separate. Existing ad-hoc Mac signing/no notarization and unsigned Windows caveats remain explicit.

No Git commit/push, remote release/tag creation, asset upload or credential/account access was performed. Native jobs now perform required work on two OS runners; no cold/warm CI duration, CPU, memory or token benchmark was run. Local publisher contract tests completed in roughly 80–90ms excluding process startup; this is not a CI performance estimate.
