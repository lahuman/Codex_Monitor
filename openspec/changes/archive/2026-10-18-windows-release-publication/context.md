# Root cause and verification

Public GitHub API inspection found a successful Windows push run (39099778983), another in-progress push run (39114100577), and an empty public Releases list. Public inspection cannot establish whether unpublished drafts exist. The local workflow had only artifact upload, no release creation or write-scoped job. This change fixes that missing producer-to-publication boundary; it does not retroactively modify an old run.

The package job retains read-only permissions, resolves its exact versioned output directory and uploads one same-run artifact with flat installer/checksum/metadata contents. A separate dependent Ubuntu job can publish only from main push/manual events in lahuman/Codex_Monitor and alone receives contents write. It checks out the tested SHA and imports the publisher through a file URL, without interpolating untrusted event text into script code. No personal access token is added.

Before mutation the publisher validates the local configuration, exact three artifact files, filename, size, SHA-256 and checksum manifest, and verifies that the run SHA is still main head. It owns a dedicated lightweight desktop version/architecture tag and a release marker for that SHA. Unrelated/annotated/conflicting refs and unowned releases are rejected. Three platform-named assets are staged in a draft and validated using GitHub asset digests or binary download hashing before publishing a prerelease with make_latest=false. Existing matching assets/public releases are reused; conflicting assets, incomplete public releases and different-commit versions are not overwritten or deleted. Partial same-commit draft failures can resume.

All five publication contract tests passed. Coverage includes draft-before-upload-before-publication ordering, same-commit no-op retry, interrupted upload retry, missing digest download validation, exact thresholds for eligibility/branch freshness, corrupted installer/manifest/checksum/extra files/path traversal, wrong version, unowned release and tag identity collision, and conflicting/missing/corrupt-download public assets. These use the production publisher with temporary artifacts and a simulated API, not an actual GitHub publication or native Windows installer. The fixture installer is explicitly non-native test data.

Actionlint passed for desktop-windows.yml. Strict OpenSpec validation passed for the active change and all 74 main specs. MkDocs strict and 92 source/document/image links passed. Runtime app code and version were unchanged; no new DMG or Windows installer was built. The existing remote native Windows success predates this publication job; running the updated workflow against real GitHub APIs remains unverified until the user pushes it. Repository/organization token policy or protected tag rules may still restrict publication and should be read from job errors rather than bypassed.

No Git commit, push, remote tag/release creation, asset upload, app installation or account access was performed. No task-level performance benchmark was run; the added network work is documented and tests complete locally in roughly 60ms excluding process startup.
