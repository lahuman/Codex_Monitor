# Menu bar monitoring context

The Rust UsageMonitor remains the sole owner of provider scheduling and observation state. A second local WebView reads the same snapshot; opening it never requests the provider directly. The pre-created hidden panel reuses the dashboard entry with a dedicated hash route, bounded account selection and existing HistoryGraph segmentation. Native main-thread AppKit renders a two-row template image using measured string widths, supporting Retina and automatic menu-bar foreground adaptation without unsafe Rust or ambient screenshots. At most four independent account status items plus overflow are rendered. Each native click closure captures the immutable account ID; a UI-thread registry owns item creation/removal and releases removed items. Presentation equality includes account IDs so an account replacement with identical visible text still updates bindings. Clicking another item switches/reanchors the panel; the same item toggles closed. Selection is mirrored through a local event and initial IPC read, with a revision guard preventing a delayed initial response from overriding a later click. The full nickname is available in the panel/native menu; the menu-bar nickname is limited to eight grapheme clusters for space.

Account labels are projected by HistoryStore using unicode-segmentation. Optional nicknames extend version-1 monitoring.json with serde-default compatibility; no account IDs or encrypted credentials change. Save/clear uses existing atomic persistence, rejects controls and overlong input, and restores in-memory nickname state on save failure. The panel's account dropdown uses full labels, while missing nicknames use three graphemes only in the compact menu bar.

Recent usage represents percentage-point decreases of observed remaining quota, not token totals. Interval baselines use the latest fresh observation minus 1/3/6 hours, selecting a preceding sample no more than ten minutes earlier. Existing five-minute sampling means totals are approximate. A missing value, unknown reset/window identity, gap over fifteen minutes, reset/window change or intermediate increase prevents a total. The existing one-hour dashboard summary now uses that same owner so it cannot silently bridge an increase. Chart lines continue to separate resets and gaps, and short histories state their actual coverage. Scheduled reset times come directly from provider observations; elapsed deadlines request a refresh rather than inventing restored quota.

Example: a work nickname appears above its 49%/72% remaining values. Left click opens the 380×640 logical-pixel panel below the status item on the selected monitor. It clamps to the work area, closes on focus loss/Escape, and suppresses the immediate mouse-up reopen when a click first blurs it. Windows keeps its explicit icon, bounded tooltip and native menu and does not instantiate the macOS panel. Native Windows behavior is not verified on this Mac.

## Menu bar typography (0.1.5)

The account name uses a regular 9pt system font and the quota uses a bold 13pt system font on a 24pt canvas, fitted to the native 22pt menu-bar height (approximately 8.25pt and 11.92pt displayed). Native NSCell font properties produce safe attributed strings; the renderer measures the styled text instead of assuming a common default font. Percentages have no leading decorative token glyph. Unknown/stale/error/paused suffixes remain meaningful state, and click targets, snapshots and polling remain unchanged. Template alpha preserves automatic native foreground colors. The renderer is also directly exercisable as an owned offscreen image for visual comparison without capturing the user's desktop.

## Sharp native text in 0.1.7

The reference screenshot places small regular CPU/GPU labels above clear medium-weight percentages. Previous native drawing rasterized on a 24pt lockFocus canvas, then reduced it to 22pt; this could resample glyphs and softened an already bold percentage. The native owner now supplies an NSImage drawing handler at its final 22pt logical size. AppKit draws its retained attributed strings at the destination backing scale. Upper labels use 7pt regular system font, lower values use 12pt medium (weight 0.23), with no bitmap resize. For example GE / 69% keeps a small name, a clear larger percentage and its existing account click identity. Urgent nickname red and semantic quota colors remain unchanged.

## Quota colors in 0.1.8

Native menu columns now carry numeric quota observations and a separate state marker rather than parsing the already formatted row. Every percentage uses its own unrounded value: >=50 green, >=25 yellow, >=10 orange, below10 red. Missing/non-finite/out-of-range values remain neutral. For example 69%/8% has independently green/red values and a neutral slash. Light appearances use darker chromatic shades for text contrast; dark appearances use native semantic colors. The existing five-second native loop repaints colored rows for appearance changes without recreating menus or adding provider reads. Nickname urgency remains separate.
