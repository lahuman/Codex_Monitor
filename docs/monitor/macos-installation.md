# Mac 설치와 실행 문제 확인

> 기능 계약: [desktop-release](https://github.com/lahuman/Codex_Monitor/blob/main/openspec/specs/desktop-release/spec.md)

## GitHub에서 받기

**Releases → desktop-v<버전> → Assets**에서 `macos-arm64.dmg` 또는 `macos-arm64.zip`을 선택합니다. 같은 릴리스에 Windows 설치 파일도 함께 표시됩니다. Mac 파일은 Apple Silicon용이며, Windows EXE와 구분하세요. Mac 체크섬은 `SHA256SUMS-macos-arm64.txt`, 배포 검증 결과는 `release-macos-arm64.json`입니다. 두 운영체제의 테스트·패키징이 모두 성공해야 통합 릴리스가 공개됩니다.

## 설치 순서

1. Mac 종류에 맞는 파일을 받습니다. `macos-arm64`는 Apple Silicon(M1 이상) 전용이며 Intel Mac에는 사용할 수 없습니다. 현재 Intel 배포 파일은 제공하지 않습니다. 최소 macOS 설정은 13.3입니다.
2. DMG를 열면 새 디스크로 마운트됩니다. 먼저 **먼저 읽어주세요.html**을 열어 보안 경고와 첫 실행 절차를 확인하세요. 설치 프로그램이 자동으로 실행되지는 않습니다.
3. 기존 앱이 실행 중이면 먼저 앱 메뉴의 ‘앱 종료’로 종료합니다. **설치하기.pkg**를 더블클릭하면 macOS 기본 설치 프로그램이 열리며 **설치 중 진행 막대 → 완료 화면**으로 상태를 확인할 수 있습니다. 설치 대상은 `/Applications/Codex Monitor.app`입니다. macOS가 관리자 인증을 요청할 수 있습니다.
4. 기존 방식처럼 **Codex Monitor.app**을 **Applications** 폴더로 드래그할 수도 있습니다. 이때 복사 진행 표시는 Finder가 관리하며, 작은 앱은 빨리 복사되어 진행 창이 잠깐 보이거나 생략될 수 있습니다. 앱이 이 표시를 제어하거나 별도의 진행률을 끼워 넣지는 않습니다.
5. 설치 또는 복사가 끝나면 DMG 디스크를 추출하고 **응용 프로그램 → Codex Monitor**에서 실행합니다.

PKG는 앱 번들만 설치하고 계정·사용 이력은 포함하거나 변경하지 않습니다. 다른 위치의 앱을 찾아서 덮어쓰지 않도록 재배치 검색을 비활성화했습니다. PKG 자체는 **미서명**이며 앱의 자체 서명과 별개입니다. 설치 파일의 개발자 확인 경고가 나올 수 있으며, Developer ID Installer 서명·공증을 완료했다고 표시하지 않습니다. 실제 시스템 설치는 배포 파일 검사와 구분합니다.

## 0.1.0에서 확인된 문제와 0.1.1 수정

기존 0.1.0 DMG와 ZIP의 체크섬은 정상이었지만 앱이 실행 파일의 링커 서명만 갖고 있어, `code has no resources but signature indicates they must be present`로 전체 앱 서명 검증이 실패했습니다. 개발한 Mac에서 실행된다는 사실만으로 다운로드한 Mac의 실행 허용 여부를 확인할 수는 없었습니다.

0.1.1은 Tauri의 전체 앱 자체 서명(`signingIdentity: "-"`)을 적용하고, 패키징 과정에서 원본 앱·복사 앱·ZIP 재추출본·읽기 전용 DMG 내부 앱 모두를 엄격하게 검증합니다. 잘못된 앱을 패키징 마지막 단계에서 조용히 다시 서명하는 방식은 사용하지 않습니다.

**자체 서명과 Apple 공증은 다릅니다.** 자체 서명은 파일 무결성을 검증하지만 개발자 신원을 증명하거나 Gatekeeper 허용을 보장하지 않습니다. 현재 Developer ID 서명·Apple 공증은 구성하지 않았습니다. `release.json`의 `signing` 항목이 실제 서명·공증 티켓·Gatekeeper 결과를 구분합니다.

## 상대방이 오류 문구를 모를 때

DMG 안의 `Diagnose-Codex-Monitor.command` 또는 저장소의 `desktop/scripts/diagnose-macos.command`를 사용하면 앱을 실행하지 않고 원인을 확인할 수 있습니다. 진단 스크립트를 복사한 폴더에서 터미널로 실행하세요.

```sh
bash Diagnose-Codex-Monitor.command "/Applications/Codex Monitor.app"
```

앱이 다른 위치에 있다면 실제 앱 경로를 사용합니다. 인자 없이 실행하면 Finder의 앱을 터미널로 드래그해 경로를 입력할 수 있습니다. 출력된 보고서 전체를 복사해 전달합니다.

보고서에는 다음만 표시합니다.

- macOS 버전·Mac/프로세스 아키텍처와 Rosetta 여부
- 앱 버전·최소 macOS·실행 파일 아키텍처
- 격리 속성 존재 여부, 전체 앱 서명 검증 결과
- 서명 메타데이터, 공증 티켓 검사와 Gatekeeper 판정

진단은 앱을 실행·설치하거나 계정 저장소를 읽지 않습니다. 격리 속성이나 보안 설정을 변경하지 않고 결과를 업로드하지도 않습니다. 검사 도구를 사용할 수 없으면 해당 오류를 그대로 출력하므로 미확인을 정상으로 해석하지 마세요. 보고서에는 선택한 앱 경로가 포함될 수 있습니다.

## 결과를 해석하는 방법

| 결과 | 의미와 조치 |
| --- | --- |
| Intel Mac + arm64 앱 | 기종 불일치입니다. Intel 또는 Universal 빌드가 필요합니다. |
| macOS 13.3 미만 | 현재 최소 시스템 설정보다 낮습니다. |
| `codesign exit`가 0이 아님 | 앱이 변조되었거나 패키징 서명에 문제가 있습니다. 승인으로 우회하지 말고 검증된 수정본으로 교체합니다. |
| 전체 서명은 정상, Gatekeeper는 rejected, 공증 티켓 없음 | 자체 서명·미공증 배포에서 발생할 수 있는 신뢰 문제입니다. |
| 모든 배포 검사는 정상인데 실행 후 종료됨 | 실행 중 충돌 등 별도 문제일 수 있으며 실제 오류/충돌 기록이 필요합니다. 이 도구는 앱 실행을 시험하지 않습니다. |

정상 출처의 파일이고 전체 서명 검증에 통과했으며, macOS가 ‘개발자를 확인할 수 없음’ 등의 경고를 표시하는 경우 Apple의 [앱 안전하게 열기 안내](https://support.apple.com/ko-kr/102445)에 따라 시스템 설정 → 개인정보 보호 및 보안의 허용 절차를 확인할 수 있습니다. 앱 손상·악성 코드·인증 취소 경고를 동일한 문제로 간주하지 마세요.

## 개발자 배포 단계

불특정 사용자에게 macOS의 신뢰 경고 없이 배포하려면 **Developer ID Application 서명과 Apple 공증**을 준비해야 합니다. Tauri는 명시적으로 설정한 `APPLE_SIGNING_IDENTITY`를 사용하며, 기본 자체 서명을 대체할 수 있습니다. 공증은 Apple이 요구하는 자격 증명과 별도 검증이 필요합니다. 자격 증명을 저장소·이슈·진단 보고서에 넣지 않습니다.

참고: [Tauri macOS 서명·공증](https://v2.tauri.app/distribute/sign/macos/)

## ‘Apple이 악성코드가 없는지 확인할 수 없음’ 경고

이 경고는 악성코드 탐지 확정과 다르며, 현재 자체 서명·미공증 배포에서 발생할 수 있습니다. 파일 무결성이 정상이더라도 악성코드가 없음을 보장하지는 않습니다.

공식 배포 원본이며 변조되지 않았음을 확인한 경우에만 앱 또는 설치 파일을 한 번 열고 **완료 → 시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기 → 인증 및 열기** 절차를 따르세요. 설치 파일과 설치된 앱은 각각 처음 열 때 확인이 필요할 수 있습니다. ‘그래도 열기’가 없거나 관리되는 Mac은 Apple 안내 또는 관리자에게 문의하세요.

악성코드 탐지·컴퓨터 손상·앱 손상·인증 취소 경고나 서명·체크섬 불일치는 위 확인 불가 경고와 구분하여 설치를 중단하고 배포자에게 문의합니다.

0.1.10부터 같은 한국어·영어 안내를 **DMG의 먼저 읽어주세요.html**, **Installation.txt**, **설치하기.pkg의 시작·완료 화면**에 포함합니다. 설치 파일 자체가 차단되어도 HTML 안내는 별도로 읽을 수 있습니다. 안내는 보안 설정을 자동으로 바꾸지 않습니다. 기준 절차는 [Apple 공식 안내](https://support.apple.com/ko-kr/102445)를 따릅니다.

[설치 프로그램 시작 안내 화면](assets/macos-installer-guide.png)에서 실제 표시 예시를 확인할 수 있습니다. 긴 안내는 화면 안에서 스크롤해 읽습니다.

0.1.11 설치 안내는 소개 페이지와 같은 크림색·코랄 색상, 단계별 카드와 글꼴을 사용합니다. 오프라인 안내와 설치 프로그램 시작·완료 화면에는 프로젝트·Releases·Mac 가이드의 정확한 대문자 `Codex_Monitor` 주소를 제공합니다. 기존 버전의 DMG는 그대로 보존합니다.
